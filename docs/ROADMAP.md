# Roadmap

The frontend is being rebuilt from scratch with a new design system (light theme by default, with a dark mode toggle). Work ships in phases, ordered by dependency. Each phase delivers working backend and frontend features together.

| #   | Phase                                   | Status   | Frontend                                                                                                  | Backend                                                                                                      |
| --- | --------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 1   | **Auth, RBAC, design system, app shell** | ✅ Done  | Design system, landing page, sign-in, sign-up (student/parent), forgot/reset/change password, route guards, a dashboard shell per role, admin user list + create teacher | Cookie JWT + rotating refresh tokens, role dependencies, first migration, SMTP + Mailpit, rate limiting, `create-admin` CLI, tests |
| 2   | Profiles & relationships                | Planned  | Profile editing (avatar, class/grade, learning level), parent↔child linking via code, full admin user management, teacher classes with join codes, optional email verification | `student_profiles`, `parent_child_links`, `classes` / `enrollments`, admin CRUD, expired-token cleanup job |
| 3   | AI doubt solving                        | Planned  | Streaming chat (text + image), history, subject/topic picker, syllabus upload for teachers and admins | Knowledge base ingestion (embeddings), RAG pipeline, LLM integration, SSE streaming, conversation storage |
| 4   | Quizzes & assessment                    | Planned  | Quiz generator, timed quiz player, results review, teacher assigns quizzes to classes                  | LLM quiz generation with teacher review, attempts, auto-grading, topic tagging                              |
| 5   | Adaptive study planner                  | Planned  | Weekly planner / agenda, task check-off, regenerate plan                                                  | Plan generation from weak topics and exam dates, regeneration via Celery                                     |
| 6   | Performance analytics                   | Planned  | Student progress charts, weak-topic recommendations, teacher class analytics                              | Per-topic mastery aggregation, analytics endpoints                                                           |
| 7   | Parent monitoring & notifications       | Planned  | Parent dashboard per linked child, reports, in-app notification centre                                    | Weekly reports by email via Celery beat, notifications table                                                 |
| 8   | Polish & production                     | Planned  | Voice input, Hindi/English i18n, PWA, accessibility audit, code splitting, Playwright E2E                   | HTTPS + secure cookies, CSP review, CI (lint, pytest, vitest), production Dockerfile fixes, monitoring       |

Future items in the app (the sidebar entries and dashboard cards marked **Soon**) are labelled with the phase that delivers them. That label comes from `frontend/src/config/navigation.js`; update it when a phase ships.
